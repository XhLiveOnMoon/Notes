OpenWrt / ImmortalWrt 在 PVE 中导入并离线扩容 overlay（实战记录）

一、目标

在 Proxmox VE 中导入 OpenWrt / ImmortalWrt x86_64 ext4 镜像，并通过 PVE 宿主机离线方式扩展 root/overlay 分区，使 opkg 可用空间增加。

最终效果：

* /overlay 可用空间从约 300MB 提升至约 900MB+
* opkg install 不再提示 No space left on device
* 全过程无需进入 OpenWrt 执行扩容

⸻

二、镜像选择

示例文件：
immortalwrt-24.10.6-x86-64-generic-ext4-combined.img

下载链接：
https://mirror.nju.edu.cn/immortalwrt/releases/24.10.6/targets/x86/64/immortalwrt-24.10.6-x86-64-generic-ext4-combined.img.gz

⸻

三、PVE 导入流程

假定openwrt的VM号为100

1. 创建虚拟机

qm create 100 –name openwrt –memory 512 –cores 1 –net0 virtio,bridge=vmbr0

根据实际情况自行调整

⸻

2. 导入磁盘

qm importdisk 100 immortalwrt.img local-lvm

⸻

3. 挂载磁盘

qm set 100 –scsihw virtio-scsi-pci –scsi0 local-lvm:vm-100-disk-0

⸻

4. 设置启动顺序

qm set 100 –boot order=scsi0

⸻

四、扩容流程（PVE离线操作核心）

1. 扩展虚拟磁盘

qm resize 100 scsi0 1G

⸻

2. 加载 nbd

modprobe nbd max_part=16

⸻

3. 连接磁盘

qemu-nbd –connect=/dev/nbd0 /dev/pve/vm-100-disk-0 –format=raw

⸻

4. 查看分区结构

lsblk /dev/nbd0

典型结构：
nbd0
├─nbd0p1  boot
└─nbd0p2  root + overlay

⸻

5. 安装工具（PVE缺失项）

apt install -y parted
apt install -y e2fsprogs fdisk

⸻

6. 扩展分区

parted /dev/nbd0

操作：
print
resizepart 2 100%
Yes
quit

⸻

7. 更新分区表

partprobe /dev/nbd0

⸻

8. 修复文件系统

e2fsck -f /dev/nbd0p2

提示：
Padding at end of inode bitmap is not set. Fix? → 输入 y

⸻

9. 扩展 ext4 文件系统

resize2fs /dev/nbd0p2

输出示例：
The filesystem is now xxx blocks long

⸻

10. 断开 nbd

qemu-nbd –disconnect /dev/nbd0

⸻

11. 启动 OpenWrt

qm start 100

⸻

五、验证结果

进入 OpenWrt 执行：

df -h

正确结果：
/dev/root 或 /overlay ≈ 900MB+

⸻

六、关键问题总结

1. 仅 qm resize 不会生效
    因为 OpenWrt 实际使用的是 overlay 文件系统，而不是磁盘大小。

⸻

2. 必须完整三步：

* PVE 扩磁盘
* parted 扩分区
* resize2fs 扩文件系统

⸻

七、最终结论

该方案实现：

* PVE 离线扩容 OpenWrt overlay
* 无需进入 OpenWrt 系统操作
* opkg 空间恢复正常
* 适用于 ext4 combined 镜像

⸻

八、建议优化（可选）

* 使用 virtio-scsi 提升 IO 性能
* 固定使用 ext4 combined 镜像避免 squashfs 复杂结构
